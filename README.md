# 📚 Практические задания (Polars & Инженерия данных)

Добро пожаловать в автоматизированную систему проверки домашних заданий! 
В этом репозитории вам предстоит решать задачи по обработке данных с использованием библиотеки **Polars**. Каждое ваше решение будет автоматически проверяться на правильность логики (Pytest), качество кода (Ruff) и строгую типизацию (Pyrefly).

---

## 🚀 Как начать работу (Пайплайн студента)

Чтобы выполнить задания и сдать их на проверку, строго следуйте этой инструкции:

### Шаг 1: Форк репозитория
У вас нет прав на прямую запись в этот репозиторий. Чтобы работать с кодом:
1. Нажмите кнопку **Fork** в правом верхнем углу этой страницы.
2. Снимите галочку *«Copy the main branch only»* (чтобы скопировалась ветка с заданиями).
3. Нажмите **Create fork**. Теперь у вас есть личная копия проекта.

### Шаг 2: Клонирование и настройка окружения
Откройте терминал на вашем компьютере и выполните следующие команды:

```bash
# 1. Склонируйте ВАШ форк на локальный компьютер
git clone https://github.com/ВАШ_НИК/AngioMorph.git

# 2. Перейдите в папку проекта
cd AngioMorph

# 3. Обязательно переключитесь на ветку с заданиями!
git checkout homeworks

# 4. Установите необходимые библиотеки (рекомендуется использовать виртуальное окружение)
pip install -r requirements.txt
```

### Шаг 3: Выполнение заданий
Все задания находятся в директории `tasks/`. Внутри каждой папки (например, `task_1_masking`) вы найдете:
* Файл с описанием задачи (обычно `.md` или комментарии в коде).
* Входные данные (`.json`).
* Файл `task_*.py` — **это единственный файл, который вам нужно редактировать**.
* Файл `test_task_*.py` — тесты. Изучите их, чтобы понять, что ожидается на выходе.

⚠️ **Важное правило:** Ваши функции в файлах `task_*.py` сейчас пустые и возвращают `None`. Вам необходимо написать логику обработки и **обязательно вернуть итоговый `pl.DataFrame`** через `return`. Иначе тесты упадут с ошибкой `[right]: NoneType`.

### Шаг 4: Локальная проверка (ОБЯЗАТЕЛЬНО)
Прежде чем отправлять код на GitHub, проверьте его локально. Если тесты упадут у вас на компьютере, они гарантированно упадут и на сервере.

Находясь в корне проекта, запустите три команды:
```bash
# 1. Проверка стиля кода (Линтер)
ruff check .

# 2. Проверка аннотаций типов
pyrefly check .

# 3. Запуск тестов логики
pytest .
```
*Добивайтесь того, чтобы все три команды завершались без ошибок (зеленым цветом).*

### Шаг 5: Отправка решения (Pull Request)
Если локальные проверки пройдены, отправьте код:
```bash
git add .
git commit -m "Решено задание 1, 2, 3"
git push origin homeworks
```
После пуша зайдите на страницу вашего форка на GitHub. Вы увидите большую зеленую кнопку **Compare & pull request**. 
1. Нажмите её.
2. Убедитесь, что вы отправляете код из вашей ветки `homeworks` в **оригинальный репозиторий** (в ветку `homeworks`).
3. Нажмите **Create pull request**.

---

## 🤖 Как работает автоматическая проверка (CI/CD)

Как только вы откроете Pull Request, GitHub Actions запустит виртуальный сервер и начнет проверять ваш код. Внизу страницы Pull Request вы увидите статус:

* 🟡 **Желтый кружок:** Проверки выполняются (обычно занимает около минуты).
* ❌ **Красный крестик:** Код не прошел проверку. Кнопка слияния будет **заблокирована**. Нажмите на *Details* рядом с крестиком, чтобы посмотреть логи, исправьте ошибку у себя на компьютере и сделайте новый `git push` (PR обновится автоматически).
* ✅ **Зеленая галочка:** Все тесты пройдены! Ваш код соответствует стандартам качества и готов к ревью преподавателем.

Удачи!
